# Solaris B — GitHub Pages

Це готова статична версія Solaris B. Збірка, сервер і сторонні сервіси не потрібні. Завантажуйте весь вміст архіву в корінь репозиторію, зберігши теки `checkpoints` і `tools`. `index.html`, `universe.json`, файли `.js`, `style.css`, `SolarisB.mp3`, `package.json`, `.nojekyll` і цей `README.md` лежать у корені.

## Публікація через сайт GitHub

1. Розпакуйте ZIP на комп’ютері. **Не завантажуйте сам ZIP у репозиторій** і не вкладайте всі файли в додаткову теку `dist` чи `solaris-export`.
2. У GitHub створіть новий репозиторій, наприклад `solaris-b`: меню **+ → New repository**, назва `solaris-b`, видимість **Public**, **без** початкового README. Натисніть **Create repository**. Для безкоштовного GitHub Pages репозиторій має бути публічним.
3. У порожньому репозиторії натисніть **uploading an existing file**. Якщо репозиторій уже має файли, виберіть **Add file → Upload files**. Перетягніть **вміст** розпакованого архіву, включно з `SolarisB.mp3`, `README.md` та `.nojekyll`. Переконайтеся, що `index.html` видно на верхньому рівні списку файлів. Підтвердьте завантаження кнопкою створення коміту.
4. Відкрийте **Settings → Pages**. У **Build and deployment** встановіть **Source: Deploy from a branch**, гілку **main**, теку **/(root)**, тоді **Save**.
5. У **Settings → Pages** натисніть **Visit site**, коли публікація завершиться. Для репозиторію `solaris-b` адреса зазвичай має вигляд `https://ВАШ-ЛОГІН.github.io/solaris-b/`. Поява або оновлення сайту може зайняти до 10 хвилин.

Щоб опублікувати наступну версію, замініть змінені файли в корені цього репозиторію й створіть новий коміт. GitHub Pages опублікує зміни з `main` автоматично. `SolarisB.mp3` — єдине джерело звуку; перший натиск на **SOLARIS** дозволяє браузеру відтворення аудіо.

## Один спільний світ

Початок Solaris: **29 вересня 2026 року, 15:00 за Стокгольмом (13:00 UTC)**. До цього моменту після натиску SOLARIS — біле поле й тиша. О 15:00 відкрита сторінка автоматично почне показувати світ. Подальші відвідувачі бачитимуть його поточний стан.

Solaris має одну спільну історію для всіх. Закриття вкладок, відсутність відвідувачів і повторне відкриття не скидають час. Сайт визначає покоління за часом, що минув від народження. Збереження стану в браузері не потрібне. Зображення і звук користуються спільним годинником; точність між пристроями приблизно до секунди за доступності серверного часу.

**Збережіть `seed` і `t0` у `universe.json` при наступних оновленнях.** Перенесення всього архіву на GitHub зберігає цю саму історію і дату народження.

## Швидке відкриття через багато місяців

Тека `checkpoints` містить точні проміжні стани, виведені з незміненого закону, приблизно на рік уперед. Сайт читає найближчий стан у минулому та обчислює лише решту поколінь до поточного часу.

Після завершення цього запасу світ продовжить розвиватися без перезапуску, але відкриття може поступово ставати довшим. Для продовження запасу на рік уперед запустіть у теці проєкту, маючи Node.js:

```sh
node tools/extend-history.mjs 366
```

Після цього опублікуйте оновлені `universe.json` і теку `checkpoints`. Ця команда не змінює дату народження чи початкові умови. Для звичайного перегляду сайту Node.js не потрібен.
